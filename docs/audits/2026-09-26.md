# QWarp performance, security, bug, and privacy audit

**Date:** 2026-09-26
**Reviewed baseline:** `6a42da5` on `audit/performance-security-privacy-bugs-2026-09-26`
**Scope:** Application runtime, subprocess and worker boundaries, IPC, settings,
local data handling, desktop integration, dependency constraints, packaging,
and CI/release workflow source.

## Assessment

Four reproducible bugs were fixed without adding features or changing intended
application behavior. The existing audit branch already contained a CI checksum
repair; that earlier work is identified separately below.

No Critical or High application vulnerability was confirmed in this review.
This is a bounded source review and regression-test result, not a security
certification. Remaining findings concern local availability, privacy,
compatibility, and supply-chain hardening. No QWarp telemetry or direct HTTP
client was found. VPN traffic and account enrollment are handled by the official
Cloudflare client and were not audited here.

## Method and limitations

Reviewed the engine, state manager, IPC, main entry point, settings/window/tray,
presentation and asset helpers, platform integration, tests, dependency files,
source archive generation, package metadata, and CI/release workflow source.
Reproduced failures with synthetic inputs and isolated local sockets before
fixing them. Checked the cited Qt advisories against the upstream publications.

Validation used Python 3.14.7, PyQt 6.11.0, and runtime Qt 6.11.2 in the existing
virtual environment, with Qt offscreen. WARP/systemd/polkit calls in affected
paths were mocked. The application was not launched against the host daemon;
no account, tunnel, service, or actual autostart configuration was changed.

Not performed: live VPN/DNS leak testing, desktop/compositor QA, adversarial
multi-process IPC stress testing, independent artifact reproduction, package
installation, a complete CVE database scan, or CPU/RSS/power benchmarking.
Remote CI results and published assets were not reverified in this pass.
Performance conclusions below describe architecture and existing tests, not
measured production latency or memory use.

## Fixed bugs

### BUG-02 — failed notification could remove a live IPC endpoint

**Severity:** Medium, local reliability
**Files:** `src/qwarp/core/instance.py`, `tests/test_instance_and_assets.py`

Previously, any failed notification led to `removeServer()`, including a
successful connection followed by a failed write, an access-denied error, or a
connection timeout. A failed notification does not establish stale ownership.

The notification result now distinguishes success, a potentially stale endpoint,
and uncertain ownership. Uncertain ownership returns `InstanceRole.ERROR`
without removing the socket. Existing missing/refused-endpoint recovery remains.
Tests reproduce write failure, timeout, and access denial and assert that no
unlink occurs. This fixes those paths, **not** the complete ownership race in
SEC-02 below.

### BUG-03 — autostart detection matched comments and unrelated groups

**Severity:** Low
**Files:** `src/qwarp/platform/autostart.py`, `tests/test_platform.py`

A comment or description containing `Hidden=true` incorrectly disabled the UI's
autostart indicator; `Hidden = true` was incorrectly reported enabled. Keys in
other groups also affected the result. Invalid UTF-8 escaped the read-error
handler, causing the combined platform query to fail.

The reader now considers exact keys only in `[Desktop Entry]`, ignores comments,
handles whitespace around assignments, and returns unavailable/disabled on an
encoding error. Boolean values remain case-sensitive. Existing generated files
retain the same behavior. Seven regression cases cover these failures. This is
not a full desktop-environment eligibility evaluator (`OnlyShowIn`, `TryExec`,
etc.). See the [Desktop Entry specification](https://specifications.freedesktop.org/desktop-entry/latest-single/).

### BUG-04 — account diagnostics could raise on numeric or null JSON values

**Severity:** Medium, UI reliability
**Files:** `src/qwarp/ui/settings.py`, `tests/test_ui.py`

Account values passed directly to translation/display code assumed strings.
A numeric quota is not accepted by `tr()`, and a null license reached `len(None)`
in the masking path. These raise in a UI slot instead of updating the dialog.

Account display values are now converted to strings, with null values mapped to
the existing translated `Unknown` placeholder. Numeric zero remains `0`.
Tests cover zero, a positive quota, and null account fields. License masking and
reveal behavior remain covered by the existing tests.

### BUG-05 — fragmented wakeup messages were discarded

**Severity:** Low
**Files:** `src/qwarp/core/instance.py`, `tests/test_instance_and_assets.py`

The server assumed one `readyRead` event contained all six bytes of `WAKEUP`.
It disconnected immediately after a partial read. A real isolated local-socket
test sending `WA` followed by `KEUP` reproduced the missed wakeup.

The receiver now retains valid prefixes, emits one wakeup on completion, and
cleans up the stored prefix on disconnect. The Qt read buffer and each read are
bounded to seven bytes, enough to recognize the command and detect excess data.
The same socket test now passes, as does ordinary primary/secondary startup.

### BUG-01 — earlier CI checksum repair, already present at baseline

**Severity:** Medium, build reliability
**Status:** Existing fix in commit `6b7e638`; unchanged in this pass

Normal CI previously checked a current-tree source archive against the checksum
of an immutable release asset. Post-release source/documentation changes could
therefore fail CI despite correct published metadata. Current CI validates its
artifact bundle against its generated checksums and adjusts Arch checksums only
inside the temporary CI checkout. The stricter release workflow still checks
candidate artifacts against committed release metadata.

The committed `v0.10.0` checksum and release version were preserved. The earlier
report's claims about remote run IDs and published asset digests are historical
evidence, not independently reverified results of this pass.

## Security and robustness findings

### SEC-01 — executable discovery trusts the user's PATH

**Severity:** Low
**Disposition:** Fixed
**Locations:** `src/qwarp/utils/process.py`, `src/qwarp/core/engine.py`, `src/qwarp/platform/taskbar.py`, `src/qwarp/platform/autostart.py`

Introduced shared `resolve_executable` validation across daemon commands, taskbar service controls, and XDG autostart. All executable lookups resolve absolute canonical paths and recursively validate the resolved file and all parent directories (including resolved symlink targets) against ownership and permission anomalies. Paths must be owned by root or the current user (restricted strictly to root for privileged executions) and must not have group- or world-writable bits set (`info.st_mode & 0o022`). Privileged operations (`repair_service` via `pkexec`) are strictly restricted to system locations (`/usr/bin`, `/bin`). Failures raise `CommandError` or `FileNotFoundError` rather than executing unsafe binaries.

**Verification:** Covered by `tests/test_hardening.py` (`test_trusted_custom_path_symlink_and_permission_revalidation`, `test_executable_missing_unsafe_path_and_privileged_custom_rejection`).

### SEC-02 — IPC ownership is not fully race-proof or explicitly per-user

**Severity:** Low, local availability/reliability
**Disposition:** Fixed
**Locations:** `src/qwarp/core/instance.py`, `tests/test_hardening.py`

Implemented atomic per-user IPC ownership using a dedicated private runtime directory (`_private_runtime()`, mode `0700`, current UID) and an exclusive lifetime Linux file lock (`fcntl.flock(LOCK_EX | LOCK_NB)` on `{sha256(endpoint)}.lock`). Ownership is acquired prior to listening or recovering stale sockets, and held continuously until after server listeners are closed. Rejects directory or socket symlinks, group/world-accessible sockets, and ownership anomalies. Dedicated lock paths are derived for test overrides (`QWARP_IPC_NAME`). The implementation safely probes same-user legacy socket endpoints (`/tmp/qwarp_ipc_socket`), notifies existing instances, and provides a legacy compatibility listener without ever unlinking the legacy endpoint. Older binaries do not participate in the new locking protocol.

**Verification:** Covered by `tests/test_hardening.py` (`test_ipc_lock_release_and_live_owner`, `test_ipc_rejects_unsafe_runtime`, `test_ipc_stale_socket_recovery`, `test_ipc_does_not_remove_symlinks`, `test_same_user_legacy_wakeup_and_compatibility_listener`, `test_simultaneous_processes_have_one_primary_and_recover_after_crash`, `test_ipc_rejects_lock_symlink`, `test_ipc_shutdown_releases_lock_when_unlink_fails`, `test_ipc_rejects_public_socket`).

### SEC-04 — accepted IPC connections have no idle deadline or total limit

**Severity:** Low, local resource exhaustion
**Disposition:** Fixed
**Locations:** `src/qwarp/core/instance.py`, `tests/test_hardening.py`

Enforced connection limits and timeouts on local IPC listeners. Active peer connections are capped at `MAX_CONNECTIONS = 16`. Each peer is assigned a strict 2-second idle message deadline (`MESSAGE_TIMEOUT_MS = 2000`). Bounded incremental `WAKEUP` buffering (up to 7 bytes) is preserved. Excess connections are aborted immediately; peers that time out or send malformed data are promptly aborted, disconnected, and have their timers cancelled. Shutdown unconditionally terminates all active connections and stops all timers.

**Verification:** Covered by `tests/test_hardening.py` (`test_ipc_idle_partial_and_malformed_cleanup`, `test_ipc_connection_limit_and_shutdown_cleanup`).

### SEC-03 — dependency versions lack artifact hashes

**Severity:** Low
**Disposition:** Fixed
**Locations:** `requirements/locks/`, `scripts/lock_requirements.py`, `requirements/README.md`, `.github/workflows/ci.yml`

Generated complete hash-locked wheel requirements files for Linux x86_64 across the full CI and release interpreter matrix (`ci-py3.11.txt`, `ci-py3.14.txt`, `minimum-qt-py3.11.txt`, `release-py3.11.txt`, `release-py3.14.txt`). CI installations use `python -m pip install --require-hashes --only-binary=:all: -r requirements/locks/...`, followed by project installation via `python -m pip install --no-deps --no-build-isolation -e .`. Added `scripts/lock_requirements.py` to regenerate locks and documented maintenance workflows in `requirements/README.md`. Empirically verified that altered wheel hashes are rejected by pip.

### ROB-01 — JSON transport trusts parseable output despite a nonzero exit

**Severity:** Informational, compatibility question
**Disposition:** Fixed
**Locations:** `src/qwarp/core/engine.py`, `tests/test_hardening.py`

Hardened `_run_json_command` to reject success-shaped JSON when a command exits with a nonzero return code. Nonzero exits return parsed data only if the payload represents an explicit structured error (`"error" in data`) or failure status (`data.get("status") == "unable"`). Success-shaped payloads (`{"status": "Connected"}`, settings dictionaries, or boolean scalars) on nonzero exits return `None`, log an exit warning, and record `self._last_cli_failure = "command_error"`. Scalar capability outputs on zero exits, raw text fallbacks, and pre-Terms handling remain supported.

**Verification:** Covered by `tests/test_hardening.py` (`test_nonzero_success_json_is_rejected`, `test_nonzero_structured_failures_are_preserved`).

## Privacy findings

### PRIV-01 — observed data flow and existing protections

**Severity:** Informational
**Disposition:** Verified existing protection
**Locations:** `src/qwarp/ui/settings.py`, `src/qwarp/main.py`

Confirmed no telemetry, external analytics SDKs, or background HTTP connections exist in runtime code. `QSettings` stores only user UI preferences and a versioned Terms consent marker, never license keys or tokens. License display is masked with explicit user-initiated reveal, and secret values in the UI are destroyed on dialog close. Minimization of secret lifetimes in memory is preserved; secure memory erasure is not claimed for memory managed by Python and Qt runtimes.

### PRIV-03 — license and organization arguments exist in the child command line

**Severity:** Low, local disclosure
**Disposition:** Explicit upstream limitation
**Locations:** `src/qwarp/core/engine.py: set_license, register`

Cloudflare's official WARP client documents license entry and organization enrollment exclusively through process command-line arguments (`warp-cli registration license <KEY>`, `warp-cli registration organization <ORG>`). The upstream CLI provides no mechanism for passing secrets via stdin, configuration files, or environment variables. QWarp sanitizes all internal logging, diagnostic displays, and command formatting strings, but argument inspection by authorized local system observers remains an unavoidable upstream limitation.

### PRIV-04 — ordinary logs include network rule targets

**Severity:** Low, local metadata disclosure
**Disposition:** Fixed
**Locations:** `src/qwarp/core/engine.py`, `src/qwarp/core/state.py`, `src/qwarp/main.py`

User-specified split-tunnel IPs, CIDRs, hostnames, and DNS fallback domains are passed as `sensitive_values` to command runners. Both original inputs and normalized values are redacted (`<redacted>`) from all log levels (`DEBUG`, `INFO`, `ERROR`) and failure diagnostic messages while passing intact values to the CLI. In addition, worker exception handling in `src/qwarp/core/state.py` and the global `unhandled_exception_hook` in `src/qwarp/main.py` were sanitized to log only exception class names and stack locations without printing raw exception messages or source code lines that might embed credentials.

**Verification:** Covered by `tests/test_hardening.py` (`test_rule_values_are_absent_from_all_command_logs`, `test_exception_hook_does_not_log_values_or_source_lines`, `test_generic_worker_exceptions_do_not_expose_values`).

## Performance findings

### PERF-01 — responsive worker architecture with serialization costs

**Severity:** Informational
**Disposition:** Measured / no change warranted
**Locations:** `src/qwarp/core/engine.py`, `src/qwarp/core/state.py`

Measured thread contention and serialization overhead under synthetic workloads. Contention latency across 100 threads contending for `WarpEngine._command_lock` is ~101 µs, which is negligible compared to the ~10–50 ms latency of WARP CLI subprocess execution. Command serialization is an essential contract required to prevent concurrency bugs in the underlying `warp-svc` daemon. Adaptive polling intervals (10s visible, 30s hidden, 1s transition) keep background CPU utilization minimal. Worker thread pools keep the Qt event loop responsive. Speculative caching or parallel execution would risk state inconsistency and is not warranted.

### PERF-02 — bounded workers do not bound all data or shutdown latency

**Severity:** Low, local resource exhaustion
**Disposition:** Fixed
**Locations:** `src/qwarp/utils/process.py`, `src/qwarp/core/engine.py`, `src/qwarp/core/state.py`, `src/qwarp/platform/`

Replaced unbounded subprocess capture with `run_command` in `src/qwarp/utils/process.py`. Uses non-blocking I/O multiplexing (`selectors.DefaultSelector`) with bounded 64 KiB chunks, enforcing a strict 1 MiB limit per stream (`OUTPUT_LIMIT`). Exceeding the limit immediately terminates the process group via `_terminate` (SIGTERM, 0.5s wait, SIGKILL, and wait reaping) and raises `CommandError("Command output limit exceeded")`. Process cancellation via `threading.Event` is propagated to engine commands and platform tasks (`taskbar`, `autostart`). Idle worker shutdown latency was measured at ~0.29 ms, and worker shutdown cleanly interrupts in-flight platform and daemon tasks.

**Verification:** Covered by `tests/test_hardening.py` (`test_runner_bounds_both_streams`, `test_runner_accepts_limit_and_replaces_invalid_utf8`, `test_runner_timeout_and_cancellation_reap_children`, `test_pre_cancelled_command_never_spawns`, `test_shutdown_cancels_platform_worker`, `test_closed_pipes_do_not_disable_timeout`).

### PERF-03 — event-driven icon rendering

**Severity:** Informational
**Disposition:** Measured / no change warranted
**Locations:** `src/qwarp/utils/system.py`, `src/qwarp/ui/tray.py`

Benchmarked SVG icon rendering under synthetic workloads. Rendering a 32x32 pixmap from bundled SVG assets takes ~0.22 ms per icon render (measured across 500 iterations). Because tray and window icons are updated strictly on discrete state transitions and system theme changes, icon rendering accounts for a negligible fraction of execution time. An in-memory pixmap cache would introduce memory overhead and palette-invalidation complexity with no measurable performance benefit.

## Dependency and packaging review

The release constraints pin `PyQt6-Qt6==6.11.2`; the local validation runtime reports the same Qt version. Qt's advisories list 6.11.2 as a fixed version for [CVE-2026-76151](https://www.qt.io/blog/security-advisory-cve-2026-76151), [CVE-2026-78253](https://www.qt.io/blog/security-advisory-cve-2026-78253), and [CVE-2026-19248](https://www.qt.io/blog/security-advisory-cve-2026-19248). Native distro packages use the distro's Qt; their patch level is managed by distribution maintainers. The reviewed application does not use a direct HTTP client or QDom parsing and renders bundled SVGs, reducing exposure to these input paths.

Packaging invariants were verified: `packaging/arch/PKGBUILD` depends on `cloudflare-warp-bin` and packages only QWarp files. CI packages are verified to contain no Cloudflare binaries, service units, or capability hooks. AI configuration and instructions are excluded from wheels, sdists, source archives, and frozen packages.
